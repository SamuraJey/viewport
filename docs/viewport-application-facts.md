# Фактура для заявки на проект Viewport

Собрано по текущему коду и документации репозитория. Назначение: веб-сервис
для фотографов, позволяющий создавать галереи, загружать фотографии и передавать их
клиентам по ссылке для просмотра и скачивания. Заявка находится в
`output/pdf/application-template/application.tex`.

## Подтверждённые возможности

| Факт | Источники в репозитории |
| --- | --- |
| Фотограф управляет галереями и фотографиями в личном кабинете. | `src/viewport/api/gallery.py`, `frontend/src/pages/GalleryPage.tsx` |
| Загрузка фотографий выполняется пакетно через временные ссылки на S3-совместимое хранилище; подтверждение запускает фоновую обработку и создание превью. Загрузка поддерживает файлы, перетаскивание и папки. | [Загрузка файлов](photo-upload-ux.md), `src/viewport/api/photo.py`, `src/viewport/background_tasks.py` |
| Хранилище учитывает занятые и зарезервированные байты и ограничивает загрузку квотой пользователя. | `src/viewport/models/user.py`, `src/viewport/repositories/user_repository.py`, `src/viewport/api/photo.py` |
| Фотограф настраивает обложку, цветовую схему, расстояния между фотографиями и порядок снимков на публичной странице. | `src/viewport/schemas/gallery.py`, `frontend/src/components/gallery-appearance/GalleryAppearanceSection.tsx` |
| Фотограф создаёт ссылку на галерею и передаёт её клиенту. | `src/viewport/api/sharelink.py`, `src/viewport/api/public.py` |
| Клиенту не нужна учётная запись фотографа для просмотра публичной страницы. Есть просмотр снимков, одиночные скачивания и ZIP-архив галереи. | `src/viewport/api/public.py`, `frontend/src/pages/PublicGalleryPage.tsx` |
| Интерфейс адаптирован для телефонов и компьютеров, поддерживает светлую и тёмную темы. | [Мобильный интерфейс](mobile-owner-ux.md), `frontend/src/stores/themeStore.ts`, `frontend/src/index.css` |
| Дополнительно реализованы видео и поворот фотографий с сохранением исходника. В заявке акцент оставлен на доставке фотографий. | `src/viewport/schemas/photo.py`, [Поворот фотографий](photo-rotation.md) |

## Технологическая основа

Ниже зафиксирован стек текущего репозитория как справочная фактура.
В заявке конкретные технологии не предписаны: команда выбирает средства реализации,
а компетенции описаны через клиентскую и серверную разработку, API, базы данных,
загрузку файлов, фоновые задачи, контроль версий, развёртывание и тестирование.

- Клиентская часть: React, TypeScript, Vite, Zustand и Tailwind CSS
  (`frontend/package.json`, `frontend/src/`).
- Серверная часть: Python, FastAPI, SQLAlchemy и Alembic (`pyproject.toml`,
  `src/viewport/`). Текущий `pyproject.toml` требует Python 3.14;
  старое указание версии Python в README не использовалось.
- Данные и фоновые задачи: PostgreSQL, S3-совместимое хранилище, Redis, Celery
  (`docker-compose.yml`, `src/viewport/main.py`).
- Проверки: pytest для сервера, Vitest для клиентской части
  (`pyproject.toml`, `frontend/package.json`).

## Как фактура использована в заявке

Цель описывает упрощение передачи фотографий клиентам через галереи.
Раздел результата перечисляет сценарии галерей и материалы для сдачи.
Критерии приёмки сформулированы как проверяемые сценарии: создание галерей,
настройка оформления, загрузка и превью, квоты, просмотр и скачивание.
Инструкции и презентация указаны как ожидаемые материалы сдачи; наличие готовой
презентации не утверждается. Функциональная приёмка приложения в рамках подготовки
документа не проводилась.

Адрес практической подготовки сохранён из образца:
Свердловская область, Екатеринбург, Мира, 19.
Автор документа удалён; заказчик, контакты и реквизиты заменены заглушками.
Семестр оставлен из шаблона: осенний семестр 2026/2027 гг.
